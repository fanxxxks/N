## §1 恒等式（规范性定义）

设某交易会话：
- **E** = 交易前权益（pre-trade equity）；
- **a_i** = 实际交易后第 i 名股票名义 / E（用户口径：名义在成交时点固定）；
- **c** = 实际费用总额 / E（**分母是交易前权益**——与现行两侧实现一致：`ashare_execution.py:179-194` 除以交易前 capital；`backtest.py:373` 除以 `capital_before`）；
- **r_i** = 下一期该股票收益（复权开盘到开盘）；
- 现金（交易后、收益前）= `(1 − Σa_i − c)·E`（现金零收益）。

**四式（冻结）**：
```
(1) g     = Σ a_i·r_i
(2) R_net = g − c
(3) w'_i  = a_i·(1+r_i) / (1+g−c)
(4) w'_cash = (1 − Σa_i − c) / (1+g−c)
```

**推导步骤（从权益演化出发）**：
```
E' = Σ a_i(1+r_i)·E + (1−Σa_i−c)·E        （股票名义按 r_i 漂移；现金不动；费用已在成交时从现金支付）
   = E·(Σa_i + g + 1 − Σa_i − c)
   = E·(1 + g − c)                          → 即 (2)：R_net = E'/E − 1 = g − c
两侧除以 E' = E·(1+g−c)：
w'_i    = a_i(1+r_i)/(1+g−c)                → (3)
w'_cash = (1−Σa_i−c)/(1+g−c)                → (4)
```

**自洽校验（代数恒等，p53/p52 测试可直接用）**：
```
Σw'_i + w'_cash = [Σa_i + g + 1 − Σa_i − c]/(1+g−c) = (1+g−c)/(1+g−c) = 1   恒成立
```

**排序语义（冻结）**：费用在成交时点从**现金**支付；股票名义在成交时点固定为 `a_i·E`，此后仅按 `r_i` 漂移。现金是零收益账户。

**可行性约束（硬性，来自用户原文"实际买入必须先满足费用后现金非负"）**：
```
(C1) Σa_i + c ≤ 1   （等号当且仅当现金恰为 0；现金任意时刻 ≥ 0）
```
违反 (C1) 的会话（Σa + c > 1，即费用融资不足）是**不可行状态**：实现必须要么使构造器端从不产生它（费用预留），要么 fail-closed 拒绝产出数值——**不得**用最终权重归一化把 Σw' 缩回 1 来掩盖（§3.4 反例）。

**多期复合（冻结）**：逐期迭代 `E_{t+1} = E_t·(1+R_net,t)`；每期的 `w'` 向量与 `w'_cash` 构成下一期交易前账本（下一期的 a 由构造器在该账本上决定）。

## §2 乘法 (1−c)(1+g) 与可加 g−c 的裁定

### §2.1 差异恒等式与经济含义
```
(1−c)(1+g) − 1 − (g − c) = −c·g
```
数值例（§3.1 会话 1 的 a/c/r）：c=0.005, g=0.022：
```
旧乘法: (1−0.005)(1+0.022) − 1 = 0.995×1.022 − 1 = 0.016890
规格:   g − c = 0.022 − 0.005      = 0.017000
差:     0.017000 − 0.016890 = 0.000110 = c·g = 0.005×0.022 ✓（分数复核）
```
经济含义：乘法形式等价于**费用按比例从整个账本（含股票腿）融资**——费用切片也"参与"当期收益：g>0 时净收益被低估 c·g（费用仿佛先挣了 g 再付），g<0 时被高估 |c·g|。可加形式等价于**费用只从零收益现金支付**：费用就是 c，不与当期收益复合。

结构性等价（本会话分数验证，帮助理解旧实现的本质）：对 Σa=1 的未预留满仓，
```
(1−c)(1+g₀) − 1 = (1−c)·g₀ − c
```
其中 g₀ 为未预留毛收益——右端恰是"把目标按 (1−c) 比例缩到费后满仓（a_i ← a_i(1−c)）再套可加恒等式"的净收益（缩放使 g ← (1−c)g₀）。且旧漂移在缩放回 1 之后逐项等于费后预留版的 (3) 式（因 0.996×1.02 = 1.01592 使两个分母比值恰为 1，见 §3.4 演算）。**即：旧乘法记账在满仓情形 = "卖股票按比例付费用、现金全程不参与"；在部分投资情形（现金明明够付）也照此记账，于是净收益与漂移分母各差 c·g。**

### §2.2 裁定
**以用户口径为准：可加，R_net = g − c。** 现行 basket 的乘法形式（`reward_baskets.py:347`）与漂移分母 `(1−c)(1+g)`（`reward_baskets.py:396-402`）都必须改为本文件 §1 四式。

### §2.3 引擎事实（本会话逐行核实）：引擎整手前精确记账 g − c，并非 (1−c)(1+g)−1
对 `backtest.py` 会话循环逐步推导（行号见 §0.2）：
```
费用从现金：卖出 line 331 (cash += notional − fees)；买入 line 370 (cash −= notional + fees)；
           可负担循环 356-368 保证 notional + fees ≤ cash（现金 ≥ 0 恒成立），不可负担则 fail-closed 364-368。
股票名义不因费用缩水：marked = shares × p_entry（line 380-384，用实际成交股数）。
交易后权益：capital_post = cash + Σmarked = E − 费用 = E(1−c)（line 385）。
费后权重：weights_i = marked_i / capital_post = a_i/(1−c)（line 386）。
引擎毛收益：gross_ret = Σ weights_i·r_i = g/(1−c)（line 403）。
会话净收益：net = capital_post·(1+gross_ret)/capital_before − 1
              = (1−c)·(1 + g/(1−c)) − 1 = (1−c) + g − 1 = g − c      （line 404）★精确可加
漂移：weights_i(1+r_i)/(1+gross_ret) = [a_i/(1−c)](1+r_i) / [(1+g−c)/(1−c)]
     = a_i(1+r_i)/(1+g−c)                                             （line 431-436）★精确等于 (3) 式
隐含现金：1 − Σweights = (1−Σa−c)/(1−c) ≥ 0（可负担循环保证）。
```
数值复核（§3.1 会话 1 输入，分数精确）：
```
weights = a/(1−c) = (0.30,0.20,0.10)/0.995 = (0.301507537688, 0.201005025126, 0.100502512563)
gross_ret = g/(1−c) = 0.022/0.995 = 22/995 = 0.022110552764
net = 0.995×(1+22/995) − 1 = 0.017000 = g−c ✓（与旧 basket 的 0.016890 差 0.000110 = c·g ✓）
引擎漂移 = 110/339 = 0.324483775811 = 规格 (3) 式之 w'_0 ✓（两算式分数同值）
```
**因此**：
1. `reward_baskets.py:342-345` 注释"((1 − cost)·(1 + gross) − 1) — the same exact form the p35 engine books"**不精确**：公式形状相同，但括号内 gross 的权重基不同——basket 用目标权重上的 g，引擎用费后权重上的 g/(1−c)——净效果相差 c·g。`tests/test_p3_portfolio_parity.py:76-78` 的同形表述同理；侦察 map §1 引擎行（"引擎…同为乘法形式 (1−c)(1+g)−1（整手前精确同形）"）**同此勘误，以本节推导为准**。
2. 16-A 是 **basket 向引擎真实记账收敛**，不是背离：修完后 basket↔engine 的 c·g 差额（p45 面板尺度 g≈0.01108、c≈1e-3 → ≈1.1e-5）从对账中消失，只剩整手/费用地板残差。**此推断必须由 p52 实测（跑 p3 parity 套件）确认，不得假设。**
3. 引擎不改（红线 4）；其整手取整只影响 a^exec ≠ a^target（§4 通道 2），不影响上述代数。

## §4 容差与整手误差的单独归因通道

### §4.1 无整手误差时的严格一致容差（冻结）
- 容差：**相对 1e-12**：`|impl − hand| ≤ 1e-12 × max(1, |hand|)`，对净收益、下一期权重（逐名）、现金三分量同标准（采纳任务书建议值 1e-12；与既有零费锚 `test_reward.py:996-998` 的 abs=1e-12 量级一致，双精度舍入 ~1e-16 经三期复合与 canonical round-12 投影后留 4 个量级余量）。
- 适用前提：lot_size = 1 且价格构造使名义整除（无整手残差）、无最低佣金地板触发（或费率为 0）。

### §4.2 整手误差的单独归因通道（冻结）
恒等式在**实际成交量**上精确成立（§2.3 引擎推导用的就是实际股数）。整手只造成 `a^exec_i ≠ a^w_i`（权重空间目标）。定义：
```
a^exec_i = 实际成交名义_i / E（引擎：floor 整腿名义，backtest.py:319-326/348-353）
ε_i = a^exec_i − a^w_i ∈ (−L·p_i/E, 0]（买腿 floor；L = lot_size，p_i = 入场原始开盘价）
```
- **通道 1（恒等式检验）**：basket 实现自身输出 vs §3 手算（同一组 a），容差 §4.1 的 1e-12 相对——**永不吸收整手残差**（构造无整手输入）。
- **通道 2（basket↔engine 对账）**：差额单独归因为三项并分别报告：
  1. `Δg = Σ(a^w_i − a^exec_i)·r_i`（整手残差的收益项；每名上界 |ε_i|·|r_i| ≤ (L·p_i/E)·|r_i|）；
  2. `Δc = c^w − c^exec`（费用差，含**最低佣金地板**非线性：名义 < min_commission/rate 的腿费用被抬高，`ashare_execution.py:116-120`——必须单列，不得并入线性项）；
  3. 尾部对齐残差（窗口末端无完整出口的列，16-B F3/F4 负责）。
  通道 2 容差用 p45 既有 `parity_bounds` 机制界（p45 §2 B2/B4 惯例，`test_reward.py:1021` 现行用法），**不复用** 1e-12。
- 两通道分离的验收含义：lot > 1 的构造下，通道 1 仍须 1e-12（basket 自洽），通道 2 按三项归因报告且各残差不超过其上界。
