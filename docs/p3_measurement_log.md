# P3 组合与因果性真实测量日志

> 本日志记录 P3 验收入口在真实本地 loader 数据上的一次确定性运行。它验证执行一致性、
> 标签不重叠、10 万元订单结构和固定裸因子四象限，不是 Alpha、显著性或可交易性证据。

## 1. 复现命令与产物

在仓库根目录运行：

```powershell
python -m ashare_model.p3_measurement `
  --config config/ashare_config.yaml `
  --output data/p3_measurement.json `
  --factor REVERSAL_5 `
  --seed 20260829 `
  --stocks 60 `
  --dates 126 `
  --runtime-repeats 3 `
  --min-eligible 100
```

运行成功退出，原始产物为 `data/p3_measurement.json`：

- 生成时间：`2026-08-29T03:36:16+00:00`（Asia/Shanghai `11:36:16`）

  `e20390572fdc286f68b6e70317f4ae1ef6647dff906b571d9d59dc0cae898b40`
- 代码提交：`54c8bcfac5bee46a10498964f68e6a9e345997ec`
- 分支：`codex/p3-portfolio-causality`

- 环境：Windows 11 `10.0.22621`、Python `3.13.12`、NumPy `2.5.2`

## 7. 受控 pre-P3 / P3 默认对照

这不是把历史 commit 或旧二进制与当前代码做墙钟对比；`pre_p3_compatible` 是在当前
引擎中关闭 P3 缓冲/阈值/最小金额/换手预算，并恢复 Top-30 的受控兼容配置。
两行严格保持以下不变量：同一 signal、dates、stocks、PIT universe、执行延迟、
初始资金与全部费用。每个配置先做一次不计时 warm-up，再交替运行 3 次。

## 8. 版本、迁移与限制

本次代码语义版本为：reward v14、protocol v22、execution v2、portfolio constructor
v1、bare-factor v3、P3 measurement v3。

- 旧 strategy、protocol 和 bare-factor JSON 不删除、不转换，仍可 archive；manifest
  记录其真实版本、配置、legacy 状态和原因。
- legacy stamp 只增加标记和时间戳，不伪造 reward/protocol/execution/constructor/
  config 字段。
- simulation 可为复现读取旧策略，但明确警告；旧结果不能作为 champion/promotion
  证据。
- promotion 拒绝 legacy，以及缺失或不匹配的 v14/v22/v2/constructor/完整配置。
- 升级必须重新训练或重新运行；手工补 JSON 字段不构成升级。
- 外部 target weights 必须由当前 constructor 重建并携带完全匹配的 provenance。

运行期间出现两个非致命诊断 warning：无可用容量行触发 `All-NaN slice`，以及 ADV=0
时 optimizer 的除零提示；产物中的四象限指标均为有限值，执行一致性校验通过。该
测量只覆盖固定 seed 的 60×126 样本；runtime 受当前机器负载影响，裸因子收益也没有
做多重检验或样本外显著性裁决。后续完整 pytest 与 main 合并验证单独执行，不能用
本日志替代测试，也不能用测试替代本日志的真实运行证据。
